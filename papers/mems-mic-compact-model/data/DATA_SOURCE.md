# Data provenance

This paper is **model-driven**: every quantitative result is produced by the
code in `../code/` and stored in `results.json`. There is no measured data set
generated by the authors, and none is fabricated.

## `results.json`
Written by `code/verification.py`. Contains, for three diaphragm designs, the
figures of merit from both the full finite-element reference
(`fem_reference.py`) and the reduced-order compact model (`compact_model.py`),
their relative errors, and the wall-clock timings behind the speed-up claim. The
`reference_summary` block is the full operating-point report of the headline
design (1 mm radius, 6 µm gap, 10 V bias, 10 mm³ back cavity).

## `commercial_anchors.csv`
Published **headline** specifications (sensitivity in dBV/Pa, A-weighted SNR) of
four shipping **analog** capacitive MEMS microphones, used only to show that the
compact model's predicted operating range is physically realistic — a
qualitative anchor, not a per-part fit.

These are the marketed figures from each manufacturer's public datasheet.
Because datasheet revisions change and some numbers are output-format dependent
(analog dBV/Pa vs. digital dBFS), **each value must be re-verified against the
current datasheet revision before camera-ready submission**, and the exact
document number/date recorded in the `source` column. This mirrors the
"do not invent numbers; cite a primary source" policy of the sibling
`ICAIET-2026/data/commercial_anchors_TEMPLATE.csv`.

No claim is made that the compact model was *calibrated* to these parts; they
bound the plausible design space only.

## Reproducing
```bash
cd ../code
python verification.py     # -> ../data/results.json   (full FEM, a few minutes)
python make_figures.py     # -> ../figures/*.png
python -m pytest -q        # validation suite
```
